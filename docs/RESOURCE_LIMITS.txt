Companion import and download resource boundaries

ROMARR_MAX_DOWNLOAD_BYTES (default 68719476736, 64 GiB)
  Maximum streamed bytes for one direct/debrid download. Both advertised and
  actual bytes are checked. Excess data is refused; private partials are removed.

ROMARR_MAX_IMPORT_BYTES (default 68719476736, 64 GiB)
  Maximum total output bytes copied by one import operation, including every
  game/member in a bundle. DAT verification has a separate budget of the same
  size. Set a positive integer number of bytes to change this operator limit.
  A bundle can import earlier complete games before its remaining budget runs
  out; it never publishes an incomplete game as successful.

ROMARR_IMPORT_TIMEOUT_SECONDS (default 600)
  Maximum runtime of each libarchive/bsdtar invocation. A timer terminates a
  stalled archive process, including a process that produces no stdout.

Disc metadata reads (CUE/M3U/GDI) and archive listing output are limited to
1 MiB. An import accepts at most 10,000 member names. Raw and ZIP DAT hashing
streams data rather than holding complete ROMs in RAM. libarchive verification
spools a bounded member to temporary storage before streaming its hash.

These are process-level limits, not disk quotas. Configure adequate free space
and container/volume quotas. A filesystem-full error refuses the incomplete
publication and cleans its staging directory.

Filesystem behavior
  Source file symlinks are rejected; source directory members and output
  paths must remain inside their configured roots. Completed files publish
  from private, unique staging paths. No-overwrite publication uses a hardlink
  so another import cannot be overwritten between an existence check and a
  rename. Download/library filesystems must support hardlinks; unsupported
  filesystems fail closed rather than silently replacing existing files.

  Multi-file sets are fully staged before publication. An explicit overwrite
  retains the old complete set until the new set is ready. If both publication
  and rollback fail, the old set remains under .romarr-previous-* for recovery
  and its location is logged. The application does not provide filesystem
  isolation against a privileged local attacker who can concurrently replace
  directory paths or modify the application's own files.
